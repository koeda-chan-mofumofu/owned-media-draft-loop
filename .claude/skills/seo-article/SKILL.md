# SEO記事 下書き作成スキル

## 入力

- 狙うキーワード（複数可）
- 記事の元になる素材（自分の経験、確認済みの一次情報、メモ等。`source/inbox/`、`source/approved/`）
- （あれば）競合記事の見出し構成メモ（`source/briefs/`）

## 手順

1. 検索意図の整理
   - キーワードから読者が知りたいこと・解決したい悩みを言語化する
   - 手動でのWeb検索で上位記事の見出し傾向を確認するのはよいが、有料APIなどによる自動収集は行わない
2. 記事構成（見出し）の設計
   - 検索意図に対応する基本構成（定義 → 分類・比較 → 選び方 → まとめ 等）を組み立てる
   - 差別化ポイント（自分の経験・独自の視点）をどの見出しに入れるか決める
   - 構成を `source/briefs/` に記録する
3. 本文執筆
   - ですます調で統一する（だ/である調は使わない）
   - 1文50字以下を目安に、段落は3行程度でまとめる
   - 各見出し（H2/H3）の直後に1〜3行のリード文を入れる（いきなり箇条書き・表に入らない）
   - 箇条書きを3つ以上連続させない（間にリード文か表を挟む）
   - 一人称の体験・観察を2箇所以上入れる
   - 目標文字数の目安：3,000字以上（テーマにより調整）
4. AI感排除チェック（該当箇所は修正する）
   - [ ] 「場合もあります」「可能性があります」など曖昧な結論のまま放置していないか
   - [ ] 「〜することが重要です」が3回を超えていないか
   - [ ] 文末表現（です/ます/でしょう/体言止め）が単調に連続していないか
   - [ ] 「これにより」を使っていないか
   - [ ] 「検討することをおすすめします」のような弱い言い回しを「してください」等に置き換えたか
5. メタ情報の下書き
   - タイトル案を3つ（30字目安、キーワードを含む）
   - メタディスクリプション案（120字目安）
6. セルフチェック（すべて通るまで修正）
   - [ ] `source/approved/` に根拠がない数値・固有名詞・日付・引用に `[要確認]` を付けたか
   - [ ] 誇張表現・断定しすぎる表現がないか（`docs/editorial-policy.md` の避けたい表現を確認）
   - [ ] 見出し構成が検索意図に対応しているか
   - [ ] 一人称の体験・独自性が入っているか
7. `output/draft/YYYY-MM-DD/記事スラッグ.md` に本文を、同ディレクトリに `titles.md`（タイトル案3つ）と `meta.md`（メタディスクリプション案）を保存する

## 禁止

- 公開・送信はしない。下書き保存まで
- WordPress等外部サービスへの自動投稿・自動編集（内部リンク追加を含む）・自動削除は行わない
- APIキー・トークンを使った外部データの自動収集は行わない
- 根拠のない断定をしない
- 太字記号 `*` の乱用
